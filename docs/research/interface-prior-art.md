# Interface prior art

- **Question:** How do agentic coding products, game-creation tools, creative tools and human–AI interaction research present agent work, running software, alternatives, feedback and authority? Which patterns suit Playstead's interface?
- **Date:** 2026-10-14 and 2026-10-15. All sources were accessed on these dates.
- **Method:** Three research passes from primary sources: official documentation, changelogs, product posts, source code, papers and practitioner talks. Sub-passes covered Lovable, Replit, Bolt and v0 in detail. No product was used; nothing below is observed behaviour. Spot-checked against the source: Anthropic's 93% approval figure, Roblox's plan rule and Cursor's frozen-frame annotation.
- **Labels:** **Documented** (official source), **Source** (code), **Paper**, **Practitioner** (talk or essay by the person who did the work) and **Inference** (reasoning, not evidence).
- **Use:** [Interface concepts](interface-concepts.md) builds proposed concepts on these findings. Nothing here is confirmed design.

## Summary for Playstead

- **No product examined documents a label on its live preview saying which version it shows.** Coding agents show whatever the development server serves; app builders tie a view to a version only in history views. Engines do signal the running copy, loudly. Showing the loaded revision beside edited source is open ground for Playstead and a requirement of its [development layer](../DEVELOPMENT-LAYER.md#changing-the-game).
- **Layouts have converged.** Coding agents use a session list, the conversation and a tabbed panel (Changes, Terminal, Files, Browser). App builders put chat beside a live preview with code one tab away. Both serve non-programmers through presentation modes, not separate products.
- **Activity is summarised and expanded on demand.** One record drives a one-line status, a list of changes and the full trace.
- **Pointing at the running product is now common.** Marks on a frozen frame or annotated screenshot become agent context. None records which revision was marked.
- **Comparison is the weakest area.** Parallel attempts and best-of-N are common; side-by-side judgement of outcomes is missing everywhere examined. Research shows that a design judged alone gets inflated ratings.
- **Approving each action is weak oversight.** Users approve 93–97% of Claude Code prompts. Vendors and researchers favour approving plans or bounded scopes, an action ledger, and an always-available stop. Plans should never lapse into consent.
- **Restore must say what it restores.** Products separate code, conversation and data. Restores that destroy the person's own edits or cannot be undone are the main failure.
- **Phone supervision has one shape.** Work runs on the person's computer. The phone pairs by QR code; it is used to steer, approve, review compact evidence and receive "needs you" notifications. Raising authority, credentials and spending stay at the computer.
- **Game playtests need context.** Useful feedback carries the build, start state, image or clip and the person's timestamped words. Valve weighs what players do over what they say.

## 1. Agentic coding products

### Layout

- **Coding agents (Documented).** The Codex app launched with "a project sidebar, thread list, and review pane" ([changelog](https://learn.chatgpt.com/docs/changelog), 2026-02-02); Codex now lives in the ChatGPT desktop app. Claude Code desktop has draggable panes for chat, diff, browser, terminal, plan, tasks and subagents ([desktop](https://code.claude.com/docs/en/desktop)). Cursor 3's Agents Window runs local, worktree, cloud and SSH agents ([3.0](https://cursor.com/changelog/3-0)).
- **T3 Code (Source).** The right panel has Browser, Terminal, Files, Diff, Pull request and Device tabs (`RightPanelTabs.tsx` at `bf8ffe8`). A browser the agent opens "floats over the chat" ([devices.md](https://github.com/pingdotgg/t3code/blob/main/docs/user/devices.md)).
- **App builders (Documented).** Lovable's Preview is "the home tab"; since 2025-05-24, "Edit Code" opens the preview instead of code ([code mode](https://docs.lovable.dev/features/code-mode), [changelog](https://docs.lovable.dev/changelog)). Replit's Agent 4 uses "Agent chat on the left and Preview on the right" ([build in parallel](https://docs.replit.com/learn/build-in-parallel)). Bolt and v0 are preview-first, with Code a toolbar mode ([v0 code editing](https://v0.app/docs/code-editing)).

### Activity

- **Collapsed summaries (Documented).** Claude Code's view modes are Normal ("Tool calls collapsed into summaries"), Thinking and Verbose ([desktop](https://code.claude.com/docs/en/desktop)). Replit groups tool calls into rows with stacked icons, each edit linking to its diff ([changelog 2026-01-16](https://docs.replit.com/updates/2026/01/16/changelog)). Lovable's activity cards open a Timeline and a Changes tab ([chat](https://docs.lovable.dev/features/projects/chat)). v0's "Work Details" shows time worked, files and lines changed and credits.
- **One record, several depths (Documented).** Vercel on v0's message parts: "The same object can drive a one-line status, a changed-files view, or the full trace" ([new v0 API](https://vercel.com/blog/introducing-the-new-v0-api), 2026-08-05).
- **No overclaiming (Source).** T3 Code's activity log states that "an interrupt or cancellation request does not mean the thread stopped" ([activity-log.md](https://github.com/pingdotgg/t3code/blob/main/docs/user/activity-log.md)).
- **Attention states (Documented).** `claude agents` groups sessions as Ready for review, Needs input, Working and Completed ([agent view](https://code.claude.com/docs/en/agent-view)). Codex's Activity view lists unread, running and waiting chats. GitHub Mobile's Live Activities show In progress, Completed, Failed and Cancelled ([changelog](https://github.blog/changelog/2026-02-26-github-mobile-track-coding-agent-progress-in-real-time-with-live-notifications)).

### Authority

- **Per-action prompts (Documented).** Claude Code offers "Yes / Yes, and don't ask again for … / No", and a comment added with Tab "becomes the denial reason" ([permissions](https://code.claude.com/docs/en/permissions)). Codex's CLI offers "No, and tell Codex what to do differently" (Source). Cursor's approval cards state why they appear ([release notes](https://cursor.com/docs/release-notes/agents-window)). T3 Code labels the request type and shows a `1/N` count (Source, `ComposerPendingApprovalActions.tsx`).
- **Automatic review by default (Documented).** Claude Auto became the default for Pro, Max and Team on 2026-08-14 ([w32](https://code.claude.com/docs/en/whats-new/2026-w32)); Cursor deprecated "Ask Every Time" ([run modes](https://cursor.com/docs/agent/security/run-modes)). Vendors limit the claim: "Changing who reviews a request doesn't expand the sandbox" ([Codex auto-review](https://learn.chatgpt.com/docs/sandboxing/auto-review)); "Approvals are a workflow convenience, not a security control" ([GitHub](https://docs.github.com/en/copilot/concepts/agents/cloud-agent/about-automation-rationale-and-approvals)). T3 Code's initial default is Full access ([permission-modes.md](https://github.com/pingdotgg/t3code/blob/main/docs/user/permission-modes.md), Source).
- **Plan approval (Documented).** App builders approve plans, not actions. Replit's plan offers Revise, Cancel, Build here and Build in background ([plan mode](https://docs.replit.com/features/agent/plan-mode)). Lovable writes `.lovable/plan.md`, which the person edits or comments on before Approve ([plan mode](https://docs.lovable.dev/features/plan-mode)). Roblox: "Plans never auto-execute or time out into acceptance" ([assistant guide](https://create.roblox.com/docs/assistant/guide), spot-checked). By contrast, Jules "will eventually auto-approve the plan, which is set on a timer" ([review plan](https://jules.google/docs/review-plan/)).
- **Budget check-ins (Documented).** Lovable's credit check-ins pause to offer continue, adjust or wrap up ([agent mode](https://docs.lovable.dev/features/agent-mode)).

### Restore and versions

- **Separate what is restored (Documented).** Claude Code's `/rewind` offers Restore code and conversation, Restore conversation and Restore code. It does not track changes made by shell commands, and checkpoints are "not a replacement for version control" ([checkpointing](https://code.claude.com/docs/en/checkpointing)). Cursor's Restore Checkpoint "reverts files only". Lovable: "Reverting restores your project's code only" ([history](https://docs.lovable.dev/features/projects/history)). Replit restores the development database only if "Database" is ticked, never production, and later work becomes "an alternate branch of history" ([checkpoints](https://docs.replit.com/features/version-control/checkpoints-and-rollbacks)).
- **Protecting other work (Source).** T3 Code refuses to revert files when another session shares the folder, and its revert "does not undo external actions" ([composer.md](https://github.com/pingdotgg/t3code/blob/main/docs/user/composer.md)).
- **Destructive restores (Documented).** Unity AI Assistant's restore "reverts all changes after the checkpoint, whether made by Assistant or you", and you "can't move forward" again ([checkpoints](https://docs.unity3d.com/Packages/com.unity.ai.assistant@2.13/manual/automate/checkpoints.html)). GDevelop: "Restore is unavailable for local projects" ([AI](https://wiki.gdevelop.io/gdevelop5/interface/ai/)).
- **Earlier states without reverting (Documented).** Lovable's per-message Preview shows the app "as it was right after that message"; versions can be bookmarked. Bolt bookmarks and renames versions ([rollback](https://support.bolt.new/managing-projects/rollback-backup)). v0's restore "creates a new, most recent version" ([versions](https://v0.app/docs/versions)).

### Pointing at the running product

- **Documented.** Cursor Design Mode: the annotation "sits over a frozen frame of the viewport, so the agent sees the exact page state you were responding to"; you can "send another edit before the first one finishes"; "As agents finish, the app hot reloads" ([design mode](https://cursor.com/docs/agent/design-mode), spot-checked). Codex's Annotate attaches comments to clicked elements or dragged areas ([browser](https://learn.chatgpt.com/docs/browser)). Lovable's preview toolbar offers Select, Edit text, Draw annotation (which sends an annotated screenshot) and Comments ([preview toolbar](https://docs.lovable.dev/features/preview-toolbar)). v0 drops numbered comments sent as one batch. Bolt comments can be sent to the agent and show "Detached" when their element disappears ([comments](https://support.bolt.new/collaboration/comments)). Antigravity takes comments on screenshots "without requiring you to stop the agent's process" ([launch](https://antigravity.google/blog/introducing-google-antigravity/)).
- **No revision (Source, Inference).** T3 Code's annotation records the URL, comment, elements, style changes and a screenshot, but no revision (`packages/contracts/src/composerContext.ts`). Bolt's preview "displays the most recent version" ([collaborate](https://support.bolt.new/collaboration/collaborate)). Only Codex Sites ties a build to "the Git commit used for the build" ([sites](https://learn.chatgpt.com/docs/sites)).
- **Agent verification (Documented).** Claude Code's Auto-verify "takes screenshots, checks for errors, and confirms changes work". Replit's App Testing drives a real browser, records a replayable video and lets the person take over. The Roblox playtesting agent (beta) uses "the player character as an automated QA tester" ([announcement](https://about.roblox.com/newsroom/2026/04/roblox-studio-going-agentic)).

### Queue and steer

- **Documented.** Each product separates queueing from steering, picks a default and offers a modifier for the other: Codex (queue default since 2026-02-08), Replit ("Steer is the default send behavior", [steer and queue](https://docs.replit.com/features/agent/steer-and-queue-messages)), v0 (Cmd+Enter interrupts), Cursor (Send now steers "at the agent's next tool call"). Bolt: "There's no way to send a prompt that bypasses the queue." T3 Code keeps saved queued messages in order and held after a server restart (Source), as Playstead's v0 host did.

### Parallel work

- **Documented.** Replit tasks run in isolated copies on a Drafts / Active / Ready / Done board, applied to the main version or dismissed ([task board](https://docs.replit.com/features/agent/task-board)). Lovable drafts each have their own chat and preview ([drafts](https://docs.lovable.dev/features/drafts)). Cursor's `/best-of-n` "does not merge changes back" ([worktrees](https://cursor.com/docs/configuration/worktrees)); T3 Code sends one prompt per selected model, each in its own worktree. Conductor advises to "archive the others or copy the useful context into the winning workspace" ([parallel agents](https://www.conductor.build/docs/concepts/parallel-agents)).
- **Inference.** None of these offers a comparison view of outcomes.

### Two audiences in one product

- **Documented.** ChatGPT Work "Hide[s] technical details like Git or shell commands" and "Prefers nontechnical language and finished outputs" ([use ChatGPT](https://learn.chatgpt.com/docs/use-chatgpt)), over the same agent as Codex. Bolt's introduction offers "New to coding?" and "Experienced developer?" paths ([intro](https://support.bolt.new/get-started/intro-bolt)). Replit tells non-programmers to "describe the symptom to Agent instead of trying to diagnose the code yourself" ([first app](https://docs.replit.com/build/your-first-app)) while keeping Shell, Git and File History as panes.

## 2. Game-creation tools and practice

### The running copy and the source

- **Signalling the running copy (Documented).** Unity's Playmode Tint is applied "to the whole Editor when you enter Play mode, to help you identify Play mode at a glance" ([preferences](https://docs.unity3d.com/Manual/preferences-colors.html)). In Roblox Studio's client mode, "the 3D viewport has a blue border" ([testing modes](https://create.roblox.com/docs/studio/testing-modes)). Construct's debugger shows edited values in bold ([inspect](https://www.construct.net/en/animation-software/manual/interface/debugger/inspect-tab)).
- **Keeping running edits (Documented).** Unreal's Play In Editor duplicates the level and "keeps the editor's copy of the world safely immutable"; Keep Simulation Changes copies selected changes back ([in-editor testing](https://dev.epicgames.com/documentation/unreal-engine/ineditor-testing-play-and-simulate-in-unreal-engine)). Godot: "Changes made to the running game this way are not preserved when the game is stopped" ([game embedding](https://docs.godotengine.org/en/4.7/tutorials/editor/game_embedding.html)).
- **Pending and failed updates (Documented).** GDevelop's preview button becomes **Update** while a preview runs; if the update fails, "a dialog will ask you to close the preview and launch a new one" ([preview](https://wiki.gdevelop.io/gdevelop5/interface/preview/)). Unreal Live Coding warns that large changes "will behave unpredictably" ([live coding](https://dev.epicgames.com/documentation/unreal-engine/using-live-coding-to-recompile-unreal-engine-applications-at-runtime)).
- **Forgotten drafts (community report).** Roblox users report draft scripts that never reached the published game ([DevForum](https://devforum.roblox.com/t/collaborative-editing-updates/504014)).

### Live iteration is not the point on its own

- **Practitioner.** Bret Victor: "Creators need an immediate connection to what they create"; "If you're designing something embedded in time you need to be able to control time" ([Inventing on Principle](https://jamesclear.com/great-speeches/inventing-on-principle-by-bret-victor), 2012). In _Learnable Programming_: "Show the data", "We must show comparisons", and "live coding, as a standalone feature, misses the point" ([essay](https://worrydream.com/LearnableProgramming/)).
- **Practitioner.** Casey Muratori's looped live code editing records input from a memory snapshot and replays the loop while the code changes ([Handmade Hero day 23](https://guide.handmadehero.org/code/day023/)).
- **Practitioner.** Hecker and Gingold's "tower of tuning" runs from recompiling up to scripting; "Each step up the tower adds systemic complexity" ([Advanced Prototyping](https://chrishecker.com/Advanced_Prototyping)).

### Start states and time control

- **Documented.** Roblox offers Test, Test Here (avatar placed at the camera) and Run. RPG Maker MZ's Battle Test sets up actors and equipment first, and F9 opens a debug screen for switches and variables ([help](https://rpgmakerofficial.com/product/MZ_help-en/01_05.html)). Godot's embedded game bar offers pause, frame advance, game speed and selecting nodes in the running game. Unreal's Rewind Debugger records gameplay for scrubbing.

### Feedback tied to a build

- **Documented.** PlaytestCloud annotations "are timestamped at the exact time of entry" and can become clips ([annotations](https://help.playtestcloud.com/en/articles/1287860-annotations-101)). TestFlight feedback filters by app version, build, device and OS ([tester feedback](https://developer.apple.com/help/app-store-connect/test-a-beta-version/view-tester-feedback)). Unreal's `BugIt` captures a screenshot and a location you can launch back into ([API](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/UCheatManager/BugIt)). PICO-8 records an 8-second GIF with one key ([manual](https://www.lexaloffle.com/dl/docs/pico-8_manual.html)). Steam Playtest is a separate app with separate access and no reviews ([playtest](https://partner.steamgames.com/doc/features/playtest)).
- **Practitioner.** Valve: "Game designs are hypotheses / Playtests are experiments"; stress the "Importance of what people do—not what they say"; think-aloud should be "Unprompted and uncorrected" ([GDC 2009 slides](https://cdn.fastly.steamstatic.com/apps/valve/2009/GDC2009_ValvesApproachToPlaytesting.pdf)).

### AI game makers

- **Documented.** Roblox Assistant's plans are "editable Markdown documents that persist across chat sessions" and run only when you click Build ([guide](https://create.roblox.com/docs/assistant/guide)). Unity AI Assistant's Agent mode: "All modifying actions require your approval" ([modes](https://docs.unity3d.com/Packages/com.unity.ai.assistant@2.13/manual/about/assistant-modes.html)). GDevelop's Auto edit is on by default; off, it asks "Yes, just this change", "Yes, and enable auto-edit" or "No". Bezi applies edits so you can test them in the engine, then Keep or Undo ([agent mode](https://docs.bezi.com/fundamentals/agent-mode)). Rosebud places "chat with Rosie beside the live preview" and lets you "preview a version that worked before" ([tutorial](https://rosebud.ai/tutorial)).
- **Documented.** Microsoft's Muse research found creators need _consistency_, _diversity_ ("a range of gameplay variants given the same initial prompt") and _persistency_ ("incorporate… user modifications") ([blog](https://www.microsoft.com/en-us/research/blog/introducing-muse-our-first-generative-ai-model-designed-for-gameplay-ideation/), 2025).

### Design records and experiments

- **Practitioner.** Stone Librande's one-page designs answer "thick 'design bibles'" and "the disconnected nature of design wikis" with single visual pages ([GDC 2010 report](https://www.gamedeveloper.com/design/-the-goal-of-design-is-to-efficiently-communicate-ideas-)). Hecker and Gingold judge prototypes by the questions they answer. Scratch remixes link back to the original and list derivatives ([Resnick et al., 2009](https://web.media.mit.edu/~mres/papers/Scratch-CACM-final.pdf)).

## 3. Alternatives and comparison

- **Paper.** When one design is tested alone, "users give significantly higher ratings and less negative feedback" (Tohidi et al., [CHI 2006](https://www.microsoft.com/en-us/research/?p=151922)). Designers who made several prototypes before critique produced better and more varied work (Dow et al., [TOCHI 2010](https://hci.stanford.edu/publications/2010/parallel-prototyping/ParallelPrototyping2010.pdf)). Chat drives "rapid convergence on a limited set of ideas" (Suh et al., [Luminate, CHI 2024](https://arxiv.org/abs/2310.12953)). _Juxtapose_ pairs parallel code alternatives with generated tuning controls ([UIST 2008](https://hci.stanford.edu/research/juxtapose)); _Exploriants_ adds variation points and a comparison view, with a game-development case study ([2025](https://www.arxiv.org/abs/2502.20535)).
- **Documented.** Figma reviews a branch "side-by-side, or as an overlay", and restore "is a non-destructive action" ([branching](https://help.figma.com/hc/en-us/articles/360063144053), [version history](https://help.figma.com/hc/en-us/articles/360038006754)). Dev Mode's Compare changes lists edited, added and deleted layers with old and new values ([compare](https://help.figma.com/hc/en-us/articles/15023193382935)). Logic's track alternatives keep one active and swap another in "at any time" ([support](https://support.apple.com/en-au/101922)). Ableton's take lanes swap with one key at the same position, and unused takes remain ([comping](https://www.ableton.com/en/live-manual/12/comping/)). Midjourney's Vary (Subtle) and Vary (Strong) set how far a variation moves (from search snippets of [the docs](https://docs.midjourney.com/docs/variations), which blocked direct access).
- **Inference.** Usable comparison needs the same starting situation, an instant swap, a list of differences, control over how far an alternative departs, and nothing destroyed until explicitly discarded.

## 4. Oversight, uncertainty and provenance

- **Documented.** "Claude Code users approve 93% of permission prompts", leading to "approval fatigue, where people stop paying close attention" ([auto mode](https://www.anthropic.com/engineering/claude-code-auto-mode), 2026-03-25, spot-checked). In a later tester study, "Human review caught just 13.6% of dangerous commands" ([blog](https://claude.com/blog/auto-mode-default-in-claude-code), 2026-08-07). Experienced users auto-approve more and interrupt more; "effective oversight doesn't require approving every action but being in a position to intervene when it matters" ([measuring autonomy](https://www.anthropic.com/research/measuring-agent-autonomy)). Plan Mode "shifts the user's level of oversight from the individual step to the overall strategy" ([trustworthy agents](https://www.anthropic.com/research/trustworthy-agents)).
- **Documented.** OpenAI: approvers need "enough context to sufficiently understand the implications"; keep "a ledger of actions"; actions reviewed only afterwards "should be more easily reversible"; retroactive justification "is likely to produce confabulated reasoning" ([practices](https://cdn.openai.com/papers/practices-for-governing-agentic-ai-systems.pdf), 2023).
- **Paper.** Feng, McDonald and Zhang name autonomy levels by the user's role (operator, collaborator, consultant, approver, observer) and warn of "meaningless rubber stamping" ([2025](https://arxiv.org/html/2506.12469v2)). Magentic-UI users valued guards before irreversible steps and found approvals for low-risk steps unnecessary ([2025](https://arxiv.org/abs/2507.22358)). Only 17% of participants attended to Android install-time permissions (Felt et al., [SOUPS 2012](https://www2.eecs.berkeley.edu/Pubs/TechRpts/2012/EECS-2012-26.html)).
- **Paper.** Amershi et al.'s guidelines include "Make clear why the system did what it did" (one of the most violated), "Scope services when in doubt", "Support efficient correction", "Convey the consequences of user actions" and "Notify users about changes" ([CHI 2019](https://www.microsoft.com/en-us/research/publication/guidelines-for-human-ai-interaction/)). Horvitz: act only above a threshold that falls with the cost of an unwanted action, and use dialogue "to resolve key uncertainties" ([CHI 1999](https://erichorvitz.com/uiact.htm)).
- **Documented.** Google PAIR: start with "the lowest level of automation", "Give control back to the user when automation fails", and "Explain for understanding, not completeness" ([patterns](https://pair.withgoogle.com/guidebook-v2/patterns)). Apple: specific progress text ("Finding substitutions for ingredients", not "Processing…"), Edit, Undo and Retry near generated content ([generative AI](https://developer.apple.com/design/human-interface-guidelines/generative-ai)); avoid conveying confidence unless it correlates with quality, and keep attributions factual: "'Because you've read nonfiction' instead of … 'Because you love nonfiction'" ([machine learning](https://developer.apple.com/design/human-interface-guidelines/machine-learning)).

### Supervision from a phone

- **Documented.** Claude Code Remote Control keeps Claude "running locally the entire time". Permission prompts stay open "until you answer them"; other dialogs expire to "the dialog's no-action default". Pushes split into "Push when Claude decides" and "Push when actions required", suppressed while you are at the terminal. Some setup and authority changes are terminal-only ([remote control](https://code.claude.com/docs/en/remote-control)).
- **Documented.** Codex in the ChatGPT app approves commands and reviews "outputs, diffs, test results, terminal output, and screenshots"; "Sandboxing, security controls, and action approvals still apply"; pairing is by QR code, and remote access stops if the computer sleeps ([remote connections](https://learn.chatgpt.com/docs/remote-connections)). Its 2026-10-07 changelog: "Status updates no longer appear as questions that need an answer."
- **Documented.** Cursor removed pushes for finished turns, keeping those for questions and approvals ([cloud agents notes](https://cursor.com/docs/release-notes/cloud-agents)). Copilot remote control: "The first response from either device wins" ([docs](https://docs.github.com/en/copilot/concepts/agents/copilot-cli/about-remote-control)). Lovable's and Replit's apps swipe between chat and preview and notify when work is ready or needs input ([Lovable](https://docs.lovable.dev/integrations/lovable-mobile-app), [Replit](https://docs.replit.com/features/platforms/mobile-app)).
- **Documented.** CISA recommends number matching against push-approval fatigue ([fact sheet](https://www.cisa.gov/sites/default/files/publications/fact-sheet-implement-number-matching-in-mfa-applications-508c.pdf)). Home Assistant's actionable notifications can require unlock (`authenticationRequired`) and mark `destructive` actions ([docs](https://companion.home-assistant.io/docs/notifications/actionable-notifications/)). Apple: "accurately represent the urgency of each notification" ([notifications](https://developer.apple.com/design/human-interface-guidelines/managing-notifications)); Live Activities suit tasks with "a defined beginning and end" ([live activities](https://developer.apple.com/design/human-interface-guidelines/live-activities)).

## Limits

- Products were studied through documentation, changelogs and source, not use. Screenshots and videos were not examined; some quotations came through a summarising fetch and may be lightly paraphrased.
- Not verified: how Codex desktop renders activity; per-hunk accept or reject in Claude and Cursor; Cursor Remote Control's design; how Roblox shows playtesting-agent results; Rosebud beyond its tutorial; any explicit "viewing an old version" banner in Lovable or v0; the length of the Jules timer.
- Midjourney's documentation blocked direct access; ChatGPT and Claude.ai branching details came from press reports; Runway was not covered.
- Several sources are vendor claims about their own products. Practitioner talks describe one team's practice.
